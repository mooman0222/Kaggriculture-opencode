# Knowledge Base (ナレッジベース)

Kaggriculture エージェント改善のための蓄積知見。**セッションをまたいでも改善が続けられる**よう、
実験・検証・メタ情報をここに記録する。

## ファイル構成

| ファイル | 内容 | 書き込みタイミング |
|---|---|---|
| `findings.md` | 検証済みの知見 (A/B テスト等で裏付けされたもの) | 有意な結果が出たとき |
| `hypotheses.md` | 未検証の改善仮説 (優先度つき) | アイデアが出たとき |
| `experiments.md` | 実験ログ (仮説・セットアップ・結果・判断) | 実験のたびに |
| `meta.md` | コンペの状況・スコアリング・本番環境設定 | メタが変わったとき |

## 記録のルール (とらわれないための最重要規則)

このナレッジベースは「**その時点の証拠の棚**」であり「正しさの集大成」ではない。

1. **必ず 日付・条件・検証方法 を書く** — 条件なしの知見はナレッジではない
   - 例: 「土地購入は逆効果」ではなく「メロン専業・デフォルト設定・vs random では -45% (2026-08-28)」
2. **上書きを歓迎する** — 新しい証拠が出たら古い記述を書き換え、変更履歴を残す
3. **実験結果と知見が矛盾したら実験を信じる** — 実験の再現性を確認してから findings を更新する
4. **条件が変わったら再検証する** — 評価設定・相手層・リーダーボード上位の戦略は日々変わる。
   ローカル実験は1試合約1.4秒と安価なので、気軽にやり直してよい
5. **「やってはいけない」も再評価の対象** — 状況が変われば正解も変わる。
   知見は行動の禁止ではなく、再評価の出発点
6. **仮説は記録してから試す** — 実験前に hypotheses.md に書いておくと、結果の解釈が明確になる
